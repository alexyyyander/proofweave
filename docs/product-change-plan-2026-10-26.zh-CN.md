# Proofweave 产品改动计划（2026-10-26）

本文把 2026-10-26 的产品判断拆成可执行的改动。它不是发布授权：生产写入、Runner 执行、数据库迁移和链上交易仍需各自批准。

## 0. 一句话目标

把 Proofweave 从“可审计的数学研究基础设施”推进到“普通人能进入、能复用、能看懂的研究公地”，同时不牺牲现有的证据真实性边界。

四个阶段：

1. **打通闭环**：让 3–10 个外部的人完整跑通一次 Person A → Runner → Person B → Receipt。
2. **建立研究公地**：让目标、前序工作、可复用引理、固定环境可以被人和 Agent 直接取用。
3. **建立理解层**：让每一个公开结论都说清楚“假设是什么、证了什么、没证什么、覆盖到哪”。
4. **建立参与阶梯**：读者、提案者、贡献者、评审者各有入口，而不是只有 Lean 专家。

## 1. 当前事实（判断依据）

- 线上 `proofweave.org` 可读，账号登录与连接生命周期为 `read_write`，participant/MCP 研究写入为 `read_only`，Runner 处于暂停。见 [发布状态](releases/2026-10-20-release-state.json) 与 [普通用户就绪度](ordinary-user-readiness.md)。
- 完整贡献链已实现但未对普通用户开放：固定目标、Attempt、Bundle、隔离 Run、独立评审、Receipt、信用市场、Nile 存证。见 [架构与路线图](architecture-and-roadmap-2026-10-13.zh-CN.md)。
- 研究重开的阻塞为 G0–G4，其中 G3（Person/Agent/Attempt 级细粒度写入门禁）尚未验证。见 [研究重开验收](research-reopening-acceptance-2026-10-20.zh-CN.md)。
- 出版目录有 719 篇稿件、372 个成果组、17 个学科；目录保留了论文结论与 Lean 覆盖范围的差异，但还没有逐结论映射到固定目标。见 [架构与路线图](architecture-and-roadmap-2026-10-13.zh-CN.md) 第 7 节。
- 目录与执行环境存在错配：文档记录 40 个目标中 39 个使用 Lean 4.27，而批准 Runner 环境为 Lean 4.31 及指定 Mathlib；OpenAI 库固定 Lean 4.34.1。大工件通道也受 1,000,000 字节/对象限制。
- 前端已有共享组件层、目标详情页、前序工作链、研究图和出版目录；`v1/` 是独立的静态设计预览，尚未接入主应用。

## 2. 目标与非目标

### 12 个月目标

1. 至少 10 位非开发团队成员完成一次真实的有界研究或评审闭环。
2. 每个公开结论都有结论卡、证明地图、Lean 对照和范围差异视图。
3. 一个贡献者可以从目标页一键取得固定环境、前序节点和可复用引理，不需要手工搭工作区。
4. 读者、提案者、贡献者、评审者四种角色各有清晰入口和状态。
5. 每个“已验证结论”的成本、时延和复用次数可以被公开度量。

### 本阶段明确不做

- 不做现金支付、证券化积分或公开结算。
- 不扩展到非 Lean 领域；先把 Lean 研究跑通。
- 不在没有细粒度门禁的情况下全量开放写入。
- 不把链上存证当作数学正确性证明。
- 不为了“覆盖所有人”而降低证据标准或伪造验证状态。

## 3. 设计原则

1. **真实性优先**：任何页面、API、工件都必须区分“来源声明”“平台重放”“独立评审”“收据”。不能由 Lean 接受推断数学正确性、新颖性或作者身份。
2. **解释工件与证据同样版本化**：解释有作者、哈希、审阅状态和更正记录；模型生成的解释必须标注并经过审阅。
3. **复用优先于新建**：目录、前序链、引理库、模板、去重信号都应在“开始研究”之前出现。
4. **最小新增权威**：优先复用现有 `external_works`、目标关系、研究图、不可变事件和收据机制，不新造平行账本。
5. **失败可解释**：每个功能都要有明确的空状态、错误状态和“为什么现在不能用”的说明。

## 4. 工作流与验收

### W0 打通闭环（P0，0–6 周）

| 编号 | 工作 | 交付 | 验收 |
| --- | --- | --- | --- |
| W0.1 | 细粒度写入门禁 | 在应用与存储实际写路径证明 Person/Agent/Attempt 级限制；越权写入拒绝；负例测试 | G3 关闭；其他身份仍被拒绝；全局 `read_write` 不再被描述为“小范围开放” |
| W0.2 | 环境对齐 | 目录目标与批准 Runner 镜像/工具链的差异报告；选定目标重新 pin 或批准新环境 | 至少一个目标可以在批准环境中真实执行 |
| W0.3 | 首案闭环 | 选定一个范围明确的公开目标，完成 Person A → Runner → Person B → Receipt 的真实记录 | 公开入口可回验签名、哈希、依赖与评审所有权分离 |
| W0.4 | 运行度量 | 记录首次贡献时间、评审时延、Run 成本、失败原因 | 指标可重复采集，不依赖手工表格 |

W0 是其他所有工作的前提。未完成 W0.1/W0.2 之前，不开展面向公众的“开始研究”入口。

### W1 研究公地（P1，4–8 周）

| 编号 | 工作 | 交付 | 验收 |
| --- | --- | --- | --- |
| W1.1 | 结论级映射 | `稿件版本 → 具体结论 → Lean 声明 → 覆盖范围 → 固定目标版本` 的数据结构与 API | 一篇论文的多个结论可以分别显示状态；不因同一成果组自动共享验证状态 |
| W1.2 | 复用索引 | 目标页展示相关目标、前序工作、可复用 Lean 路径、去重提示；API 供 Agent 读取 | 新贡献者无需手工搜索即可找到至少一个可复用前序 |
| W1.3 | 模板与一键工作区 | 每个目标自带 toolchain/Mathlib pin、允许命令、资源上限、Agent 任务说明；MCP 工具返回工作区 | 从目标页到可运行工作区的步骤可被记录且可重试 |
| W1.4 | 近似去重 | 对 Lean 命题和自然语言陈述做规范化比较，提示“可能已有工作” | 重复劳动可被显式标记为复用或反驳关系 |

### W2 理解层（P2，4–8 周，可与 W1 并行）

| 编号 | 工作 | 交付 | 验收 |
| --- | --- | --- | --- |
| W2.1 | 结论卡 | 假设、结论、适用范围、**明确未证明什么**、形式化覆盖、证据状态 | 读者 5 分钟内能回答“证了什么、没证什么” |
| W2.2 | 证明地图 | 依赖 DAG 的人话展开；节点作用、失效影响 | 专家可以从结论追溯到 Lean 声明和前序工作 |
| W2.3 | Lean 对照 | 逐行自然语言注释、关键 tactic 解释、proof state 快照 | 非 Lean 用户可以理解一段证明的主线 |
| W2.4 | 范围差异视图 | 论文原话 / Lean 陈述 / 实际测试范围并排 | 目录中已记录的范围差异（如 084、159）成为一等公民 |
| W2.5 | 三级摘要与阅读指南 | 中学 / 本科 / 专家三档；术语表；先读路径 | 每个结论至少有一档完整可读 |
| W2.6 | 解释工件的评审 | 解释绑定结论哈希、作者、审阅状态和更正 | 错误解释可以被更正，不会变成新的一抹黑 |

解释工件由模型起草，但必须与证据一样经过审阅；未审阅的解释明确标注“草稿”。

### W3 参与阶梯（8–12 周）

- 读者：结论卡、证明地图、阅读指南、订阅关注目标。
- 提案者：从论文结论或外部来源“建立复验目标”，经过整理后进入目录。
- 贡献者：目标 → Agent 连接 → 有界任务 → 证据提交的引导流程。
- 评审者：评审市场、校准、声誉、SLA；不同 Person 的独立性不可伪造。
- 验收：四种角色各有独立入口；新用户从任一入口到“下一步”不超过三次点击。

### W4 激励与结算（12 周以后）

- 评审供给：校准、声誉、有上限的评审奖励、明确的响应时延。
- 信用市场：从 draft pilot 走到可结算的非金融积分；再评估赞助和外部支付。
- 算力：配额与赞助并行，不做无上限免费 Runner。

### W5 规模与信任（持续）

- 大工件通道（>1,000,000 字节）与依赖缓存。
- 锚定批处理、公开状态页、事件历史。
- 公开指标：验证结论数、复用率、评审时延、成本、贡献分布。
- 反 Sybil、利益冲突、重复工作和图分裂审计。

## 5. 本批改动（Wave 1）

Wave 1 只做**不依赖生产写入、不改变验证边界**的切片，为 W1/W2 打底。

| 工作流 | 内容 | 文件所有权 | 验收 |
| --- | --- | --- | --- |
| A 解释层基础 | 解释工件 schema、结论卡/证明地图/Lean 对照组件、出版详情页接入、示例数据 | `packages/domain/claim-explanation.mjs`、`app/components/explanation/**`、`data/publications/explanations/**`、`app/publications/openai-math/[number]/page.tsx`、`app/publications/publications.css`、`tests/claim-explanation.test.mjs` | 出版详情页出现“证了什么/没证什么/范围/Lean 摘录”；不声称平台已验证；domain 测试通过 |
| B 结论映射 | 逐结论数据、校验器、构建脚本、只读 API | `packages/domain/publication-claims.mjs`、`data/publications/claims/**`、`scripts/ingest/build-publication-claims.mjs`、`app/api/publications/openai-math/[number]/claims/route.ts`、`tests/publication-claims.test.mjs` | API 返回逐结论记录与覆盖状态；非法数据被拒绝；不编辑页面 |
| C 复用索引 | 相似度匹配、聚合读模型、目标页复用面板、只读 API | `packages/domain/reuse-match.mjs`、`services/research/reuse-index.mjs`、`app/api/catalog/[slug]/reuse/route.ts`、`app/explore/[slug]/ReusePanel.tsx`、`app/explore/[slug]/page.tsx`、`app/explore/[slug]/ReusePanel.module.css`、`tests/reuse-index.test.mjs` | 目标页显示相关目标/前序/可复用路径与空状态；API 可被 Agent 读取；domain 测试通过 |
| D 写入门禁审计 | 只读审计 G3 的实际执行点、缺口、最小守卫设计与测试矩阵 | 无文件改动，只提交报告 | 给出 file:line 证据、缺口清单、可执行测试矩阵与风险 |

### 文件所有权与集成顺序

- A、B、C 三个工作流文件不相交；D 只读。
- A 与 B 的数据在 Wave 2 合并：B 的 claims API 成为 A 的 claim card 数据源。
- C 的复用索引在 Wave 2 接入 W1.3 的一键工作区。
- 集成顺序：B → A → C；每个工作流先通过自己的 domain 测试，再由主流程跑 typecheck/build 和目标页面测试。

### 本批明确不做

- 不部署、不推送、不提交生产配置。
- 不修改 `app/auth.ts`、`db/control-plane-authority.mjs`、`services/database/*`、`worker/cloudflare.ts`、`wrangler.cloudflare.jsonc`。
- 不新增数据库表；先用文件和只读投影验证。
- 不把解释草稿标成已审阅，不把复用提示标成已验证。

## 6. 发布与安全约束

1. 任何生产部署必须来自已提交源码的 `npm run build:cloudflare:release`，并记录 `PROOFWEAVE_RELEASE_SOURCE_REVISION`。
2. 写入开关、Runner、迁移、链上交易都按 [研究重开验收](research-reopening-acceptance-2026-10-20.zh-CN.md) 单独批准；本文不授权。
3. 不在仓库、日志或测试夹具中写入真实凭据、私有工作区或 Token。
4. 解释工件、复用索引和结论映射都必须有明确失败态；缺少数据时显示“暂无”，不显示示例冒充真实。
5. 每个工作流结束前跑相关 `node --test`、`node --check`；主流程再跑 build、typecheck（排除 `outputs/` 与 `work/*` 生成目录）和目标页面渲染测试。

## 7. 验收指标

- 首次获得可验证贡献的时间（注册 → 第一张收据）。
- 复用率：引用前序节点的 Attempt 占比；重复目标被合并的比例。
- 解释覆盖率：有经审阅结论卡的公开结论占比。
- 评审时延与评审者供给。
- 每个已验证结论的真实成本（算力 + 人力）。
- 外部贡献者 30/90 天留存。
- 读者理解度：小样本“证了什么/没证什么”测验。

## 8. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 冷启动：目标少、评审少、贡献少 | 先用出版目录导入可复验结论；用首案和 10 人闭环积累评审者 |
| 解释幻觉：模型生成错误解释 | 解释绑定结论哈希；必须审阅；草稿明确标注；可更正 |
| 复杂度：每个功能增加发布门禁 | Wave 1 只做只读切片；新表和新开关延后 |
| 成本：Lean 执行昂贵 | 配额、缓存、赞助；先测量再开放 |
| 身份与独立性造假 | 复用现有不同 Person 检查；不做账户映射的自动合并 |
| 范围蔓延 | 本文的非目标清单是硬边界 |

## 9. 时间线（相对周）

- 第 0–2 周：Wave 1 三个切片 + G3 审计；确定首案。
- 第 2–6 周：W0.1–W0.4；完成一次真实闭环。
- 第 4–8 周：W1.1–W1.4 与 W2.1–W2.6 并行。
- 第 8–12 周：W3 参与阶梯；评审市场校准。
- 第 12 周以后：W4 结算与 W5 规模。

时间线是计划，不是承诺；每个阶段以验收证据为准。缺少证据时，不进入下一阶段。
