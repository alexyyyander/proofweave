# 外部用户就绪计划（2026-10-27）

本文定义“第一批外部用户可用”的边界、门禁和验收。它不是发布授权；生产写入、Runner 执行、E2B/Render 变更和链上交易仍需各自批准。

> 2026-10-27 更新：4.27 镜像已用 Node 22.23.4 安全重建，当前登记 digest 为 `sha256:3a7e335f…`（run `40469297704`，commit `c3461cf…`）；下文早期记录的 `sha256:373c7ee…` 已被取代。Lean 4.35 的新目标方向由独立升级工作记录，不改变历史目标的 4.27 来源。

## 目标

先让 **10 位非开发用户** 在不被过度手工照顾的情况下完成一次有界研究或评审；在此之前不追求“所有人”。

## 用户分层

| 层 | 人数 | 能做什么 | 平台必须提供 |
| --- | ---: | --- | --- |
| 内部验证 | 2 | 用现有 Alex 账号跑通写入、Runner、评审、收据 | 受控窗口、单 Run 限制、回滚 |
| 设计伙伴 | 3 | 选目标、连接自己的 Agent、提交一次有界证据 | eligibility 可见、provisioning 脚本、清晰失败态 |
| 外部用户 | 5 | 阅读、评审或完成一次有界贡献 | 申请入口、评审供给、配额/成本说明、支持路径 |

## 当前状态（2026-10-27）

- 生产窗口已开放 participant + MCP 写入：2 Person / 2 Agent / 4 Attempt，gate 有效。
- Runner 可达但 `executionEnabled=false`，sandbox 仍是 4.31；目录目标是 4.27。
- 4.27 镜像已构建：`sha256:373c7ee…`，但 E2B template 与 Render env 尚未切换。
- 阅读侧：目录、719 篇论文、8 条结论映射、3 份解释草稿、复用索引。

- 大工件：内联上限 1MB；混合 D1/R2 存储代码已准备，生产尚未绑定 R2 bucket。

## 门禁

### G-A 执行链可用

1. 4.27 镜像加入 Worker 批准列表（4.31 可并存）。
2. 用该 digest 构建 E2B template，记录 template/build ID。
3. Render 更新执行镜像与批准列表，配置 `RUNNER_ONLY_RUN_ID` 与单次投递。
4. 一次受控 Run 通过：Lean accepted、四项检查、结果签名、输出哈希。
5. 通过后才允许设计伙伴提交 Runner 请求。

### G-B 写入资格可见

1. `/api/me/research-eligibility` 返回当前 Person/Agent/Attempt 是否在窗口内。
2. Workbench 在不能写时禁用创建按钮并显示原因；不把 403 留到点击之后。
3. 非白名单用户看到“申请访问”入口，而不是空白或错误。
4. operator 可以在不读代码的情况下加入/移除 Person、Agent、Attempt。

### G-C 评审供给

1. 外部用户知道如何成为评审者、需要什么委托、评审哪几类声明。
2. 评审任务有明确的领取入口、容量上限和预计时间。
3. 作者能看到“等待不同 Person 评审”的状态，而不是无限等待。
4. 至少 3 位可用评审者，评审时延有记录。

### G-D 成本与配额

1. 用户能看到 Attempt/评审/工件/执行次数限制与当前用量。
2. Runner 执行有单次预算，失败不自动无限重试。
3. 大工件路径明确：小对象内联，大对象 R2，单对象上限 32MB。
4. 免费额度和赞助/付费边界写清楚。

### G-E 理解与支持

1. 每个公开结论有结论卡、范围差异、证据状态；至少覆盖前 50 个高频结论。
2. 用户能在 5 分钟内回答“证了什么、没证什么、还差什么”。
3. 有隐私、条款、数据保留、滥用处理和联系路径。
4. 英文为主，至少中文阅读路径可用；移动端可读。

## 第一批开发（进行中）

| 工作 | 内容 | 验收 |
| --- | --- | --- |
| Eligibility API + Workbench | 当前用户资格、原因、申请入口、禁用写按钮 | 非白名单用户看到不可写原因；白名单用户看到可写状态 |
| Operator window CLI | 加入/移除 Person/Agent/Attempt、导出 env、收紧窗口 | 不手改 JSON 即可完成 provisioning；失败不半写 |
| Runner 环境配置 | 4.27 digest、cutover 检查、template/Render 状态 | 脚本明确指出 4.27 已构建但 blocked 的原因 |
| 混合工件存储 | 小对象 D1、大对象 R2、读兼容旧内联 | 旧 bundle 可读；>1MB 新对象可写；上限 32MB |
| 外部用户审计 | 路径、资格、评审、成本、错误态、内容、法律 | 给出 P0/P1/P2 清单与 file:line |

## 下一批（待第一批验收后）

1. 自助访问申请 + operator 审批记录（避免 GitHub issue 作为唯一入口）。
2. 按用户显示用量与配额（Attempt、评审、工件、Run）。
3. 评审者 onboarding 页面与评审 SLA/校准。
4. 结论卡与解释覆盖扩展到 50+；范围差异自动生成。
5. 一键目标工作区（toolchain/Mathlib/前序节点/Agent brief）。
6. 失败与 stuck 状态的可操作恢复路径。

## 指标

- 外部用户从注册到第一次成功写入的时间。
- 从提交 Bundle 到 Runner 终态、到第一位评审者领取的时间。
- 非白名单用户触发 403 的次数（应趋近 0，因为 UI 应提前禁用）。
- 每个已完成贡献的 Runner 成本与评审人力。
- 30/90 天外部用户留存与第二次贡献率。

## 边界

- 不因为“外部用户”而降低证据标准。
- 不在没有 E2B template 与 Render 切换的情况下宣称 Runner 可用。
- 不把 gate 配置、eligibility 或窗口开放描述为数学验证。
- 不在第一批用户中开放公开评审市场或现金结算。
